# Прототип Workers Free

Власник підтвердив наявність Cloudflare-акаунта та прямо доручив почати: «ну давай тоді по cloudflare поїхали, шо треба». Підготовка й локальна перевірка прототипу виконуються в межах цього доручення. Платні тарифи або ресурси не дозволені.

## Перший етап

Ізольований `naholosy-free-prototype` без даних користувачів, Firebase credentials, Play credentials, баз даних, cron і платних bindings. GET /health повідомляє prototype/productionReady=false. POST /probe/{scenario} захищені окремим випадковим 256-бітним PROBE_TOKEN. За відсутнього секрету probe закриті. Ключ зберігається локально в ignored .dev.vars та як Cloudflare Worker secret; не в чаті.

Сценарії вимірюють дві RSA-2048 перевірки синтетичних JWT, поточну validateUpload/mergeValidatedProgress, звичайні та максимально дозволені пакети, локальну оцінку fixture покупки й формування порції видалення. Синтетична JWT-перевірка приймає тестовий ключ із запиту і категорично не є production Firebase/Auth/App Check verifier. Запити обмежені 8 KiB; сценарії задані allowlist. Реальних записів/видалень/покупок немає.

## Що цей етап доводить

Dry-run перевіряє bundling, workerd-тести — сумісність API й виконання сценаріїв без зовнішніх запитів. Після авторизації у власному Cloudflare треба перевірити, що саме Workers subscription має Free, вибрати правильний account ID і розгорнути ізольований прототип. У Dashboard Metrics перевірити CPU/errors на обмеженій кількості викликів, окремо для кожного сценарію. Локальний Node/workerd wall time не є CPU Cloudflare. Наявність status=200 сама по собі теж не доводить стабільного запасу до ліміту.

Генерація fixture та JSON roundtrip додають накладні витрати: результат є попередньою оцінкою, а не точним бюджетом production endpoint. Повторне імпортування ключа (`coldKeys`) не гарантує холодного запуску isolate.

## Наступний етап

Потрібні справжній verifier довірених Google ключів із перевіркою issuer/audience/expiry/app ID та revocation policy, секрети службового акаунта з мінімальними правами, Firestore REST транзакції та Google Play API. Виміряти також отримання/ротацію ключів, OAuth, повтори транзакцій, розмір payload і порційне видалення. Жодний синтетичний endpoint не підключати до Android.

Модель Premium з 3 листопада зберігається: після видалення немає purchase claims; restore через Play після перевірки зі взаємовиключною активною прив'язкою. Попередній Firebase transport ще потребує перенесення. Сам прототип не робить застосунок готовим до релізу.
