# Перше налаштування AdMob для «Наголоси НМТ»

Дата: 2 листопада 2026. Акаунт AdMob уже підтверджено, застосунок у магазині ще не опубліковано. Реалізація використовує один звичайний повноекранний Interstitial після завершеної навчальної сесії.

Оновлення: запис застосунку й Interstitial створено. Власник надав App ID `ca-app-pub-8582558359374683~7304973975` та Ad unit ID `ca-app-pub-8582558359374683/7851321772`. Значення внесено в кореневий `gradle.properties`; release читає їх через наявні Gradle properties. Debug продовжує використовувати офіційні тестові ID. Наведені нижче кроки створення вже виконано, повторювати їх не потрібно. Налаштування ID не є підтвердженням схвалення AdMob, UMP/вікового режиму чи готовності release.

## 1. Додати застосунок

На показаному екрані:

1. Платформа — **Android**.
2. «Чи опубліковано додаток у підтримуваному магазині додатків?» — **Ні**.
3. Натиснути **Продовжити**.
4. Вказати назву, яку планується використовувати в Google Play, наприклад **Наголоси НМТ**.
5. Якщо з’явиться поле package name — **com.intervalninaholosy.nmt**. Це package застосунку; Firebase Project ID у це поле не підходить.
6. Якщо запропоновано необов’язковий перемикач User metrics, можна залишити вимкненим до завершення налаштувань приватності. Створення рекламних ID саме по собі не потребує ввімкнення добровільної діагностики застосунку.
7. Натиснути **Додати / Add app** і завершити створення запису.

Додавати неопублікований застосунок для підготовки й тестування дозволено. Після публікації потрібно повернутися та прив’язати його сторінку магазину; для повноцінного показу реклами потрібне проходження перевірок AdMob. [Офіційна інструкція](https://support.google.com/admob/answer/9989980).

## 2. Створити рекламний блок

1. Відкрити створений застосунок → **Рекламні блоки / Ad units**.
2. Натиснути **Почати / Get started** або **Додати рекламний блок / Add ad unit**.
3. Обрати **Міжсторінкове оголошення / Interstitial**. Для поточного коду потрібен саме звичайний Interstitial; Rewarded interstitial — інший формат.
4. Назва блоку — наприклад **session_complete_interstitial**. Це зручна внутрішня назва місця показу.
5. Розширені налаштування можна залишити початковими. Якщо є Frequency capping, обрати **без обмеження**, відповідно до рішення власника. Фіксований eCPM floor вручну зараз не потрібен. Це не повертає прибраний локальний рекламний ліміт.
6. Натиснути **Створити рекламний блок / Create ad unit**.

[Офіційна інструкція створення Interstitial](https://support.google.com/admob/answer/7311435).

## 3. Скопіювати два ID

| Що | Для чого | Де знайти | Вигляд |
|---|---|---|---|
| AdMob App ID | Ідентифікує застосунок у рекламному SDK | Apps → View all apps → стовпець App ID; також налаштування застосунку | ca-app-pub-…~… |
| Interstitial Ad unit ID | Ідентифікує конкретний рекламний блок | Застосунок → Ad units → створений Interstitial | ca-app-pub-…/… |

Надіслати обидва значення в чат. Це публічні конфігураційні ID. Firebase Project ID `intervalni-naholosy-nmt-prod` є окремим ідентифікатором і не замінює жоден із них. [Як знайти й скопіювати ID](https://support.google.com/admob/answer/7356431).

Після отримання значень їх можна внести в release-конфігурацію. Debug-збірка має використовувати офіційні тестові ID. Створення production ID не означає, що рекламні запити вже дозволені або що завершено UMP, віковий режим 13+, app-ads.txt і перевірку готовності застосунку. Ці кроки виконуються під час остаточного налаштування й публікації.

## Перевірка після внесення ID

`release-preflight.py` підтвердив обидва ID та відсутність перекриття іншими локальними Gradle properties. `:app:verifyReleaseConfiguration` прийняв AdMob-параметри й очікувано зупинився лише через Web OAuth client, два публічні HTTPS URL та release signing inputs. Повний release APK/AAB не збирався й не публікувався. Лог: `.local-verification/2026-11-02-admob/release-config-check.log`.
